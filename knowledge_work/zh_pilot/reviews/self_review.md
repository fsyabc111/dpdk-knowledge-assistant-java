# 编写者自审

类型：对固定快照的静态回读与自审，**不是独立审核**。两篇均待人工审核。
来源版本见 [manifest](../manifest.json)。未调用应用模型，未编译运行项目；精确编写模型运行标识、会话 token 和费用不可得，不记为零。

| 核查项 | 回读与处置 | 相关事实 |
| --- | --- | --- |
| 加载与初始化顺序 | 对照加载函数全部分支；init 失败与句柄 malloc 失败分开，不把二者 cleanup 行为混写 | PL-003、PL-005 |
| 调度与返回值 | 对照插链与整个 engine_process；HANDLED 对外变 OK，ERROR 终止；其他值继续；先计数后 can_handle | PL-006、PL-007 |
| 是否启用 | entry/registry 结构与调度未见通用 enabled；no-plugins 只描述启动加载函数，不宣称禁止所有后续热加载 | PL-004 |
| 资源清理 | 回读 destroy/unload 与会话销毁；只写可见释放范围，不承诺无泄漏，不要求插件 free 借用报文 | PL-009、PL-010、PF-010/011 |
| 多实例与并发 | 回读 worker 初始化、collect registries 和加载回滚；独立 ctx 不证明库全局变量独立；读写锁不证明插件整体线程安全 | PL-008/010 |
| 缓冲区 | payload 是原 data 偏移；单线程 release 与 worker free 分开；没有把 PCAP no-op 写成可长期持有 | PL-009、PF-005/011/013 |
| 构建路径 | 回读根与 capture Makefile，plugin Makefile 确认 registry 编入 libengine；不执行 make，不将根同名文件说成“全仓无用” | PF-001 |
| 实际调用链 | 回读 main 单线程及 worker；单线程统计在插件前，worker 任务在插件后；没有把插件 ERROR 等同退出抓包 | PF-003/007/008/013 |
| 周期与存储 | 回读回调尾部、submit 函数、worker_periodic；区分内存更新和落盘；不把回调触发的清扫当独立定时器 | PF-007/009/014 |
| 旧说明漂移 | 未复制 worker ring 旧注释与单线程 burst 图；保留原文在快照供审核，不修改主仓库旧文档 | PF-003/012 |
| 文本一致性 | 插件篇讲接口与生命周期，报文篇讲承载对象与先后；通过互链避免重复完整调度细节 | 全文 |
| 共享内容 | 样稿无部署地址、凭据、学生记录、harness 参考答案与完整 C 实现；快照为本地来源附件，不是发布正文 | 全文 |
| 命令真实性 | 只执行文档检查与静态切分；正文不含部署/抓包操作，阅读练习不作为已执行测试 | 全文 |

## 未作结论的边界

- 加载失败是否在某个具体插件内部泄漏、注册中心销毁的进程级后果：须结合实际插件与运行测试，本文不作保证。
- RSS 双向流实际落在哪个队列、多段 mbuf 如何处理、复杂短包与 IPv6 扩展头安全性：未做硬件/报文测试。
- 管理线程和 worker 并发热加载、引用返回指针的安全性、所有插件全局状态竞争：不在本批审计范围。
- 统计队列满或存储失败的完整一致性保证：仅说明本批看到的调用和丢弃分支，不写可靠落盘结论。

## 切分语义复核方法

将 `checks/chunk_preview.json` 中每个分片按其标题独立阅读，检查版本说明、比较路径、条件和来源是否明确；任何超过当前工具 1500 字符窗口的分片须回改正文。实际数量及最大长度见[验证记录](../checks/validation.md)。
这些检查只防明显切分失真，不能替代生成模型实际可见证据测试，也未验证 RAG 增益。

切分预览复读时发现一级标题曾单独形成无解释的短片段，已给两篇标题补充主题摘要，并在检查脚本中加入标题空壳检测。重新切分后未出现空壳；每个正文片段的条件、比较对象和来源行均完整保留。
