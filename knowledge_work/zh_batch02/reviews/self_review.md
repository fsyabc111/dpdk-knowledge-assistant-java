# 编写者自审（第二批 rev 2）

类型：对固定快照的静态回读与**编写者自审**。本文件不是独立审核——四篇新稿的独立审核与人工审核都尚未发生。
来源版本见 [manifest](../manifest.json)。未调用应用 LLM/embedding；精确的模型运行标识、会话 token 与费用**不可得**，不记为零。

自审方法与首批相同：写完正文后按事实编号回到源码重读，逐条确认调用点、失败分支与清理路径，
而不是重读自己的文字。下表记录重读时的问题与处置。

## 过程中发现的问题与处置

1. **一次 grep 输出与文件系统不符。** 检索“是否存在其他 DNS 实现”时，一条 grep 命令回报了 `old/` 与 `submit_code_output/` 下的同名文件。
   用 `ls`、对代码根目录执行 `find -name engine_dns.cpp` 与 `git ls-files` 直接复核后确认：这些目录不存在，全仓只有一份
   `plugin/plugins/engine_dns.cpp`。该输出按不可信噪声处理，**没有**写入任何事实；同时把“未实现清单”的范围从“全仓”
   收窄为“本版本该文件的实现里找不到”，避免依赖一次无法复现的检索（见 DR-010 的核查说明）。
2. **一次误操作覆盖了清单。** 自审期间重复运行了一个临时生成脚本，把清单里两处刚做的修订冲掉了（表现为检查报
   “引用了本批未登记的事实”）。检查脚本发现了它，修订已重新应用并复跑通过；该临时脚本随后已删除。事实表现在统一由
   [checks/build_evidence.py](../checks/build_evidence.py) 从 `manifest.json` 生成，避免正文与清单手工分头维护。
3. **rev 1 长度超出建议区间。** 两篇初稿分别 2543 与 2858 个中文字，超过 1200–2000 的建议值。压缩过程中出现只改写不删减、
   以及在“来源”行追加解释反而更长的情况；手压到 2108 与 2225 仍超限。**未放宽阈值**，而是按用户决定在 rev 2 各拆两篇，
   现为 1300 / 1631 / 1591 / 1579 字，全部回到建议区间。
4. **拆分只动结构不动事实。** 45 项事实的陈述、依据行范围与结论在 rev 2 原样搬运，只重新编号（新增 `previous_fact_id` 与
   `split_from` 血缘）并归入新章节；逐篇引用完整性由检查脚本复算，未新增或删减任何事实。
5. **首批审核中登记的定位缺陷未在本批重犯。** 本批所有事实的定位符号都必须出现在所引行范围内，由检查脚本逐条验证。
