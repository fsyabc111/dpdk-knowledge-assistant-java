- 保留 harness 独立仓库、容器隔离、内网与资源限制，不在宿主机或后端直接执行学生代码。

- 保留权限与班级隔离、凭据不入库/日志/文档、Markdown 消毒和既有 API/SSE 兼容要求。
- 保留 token/上下文/时间护栏及用量统计；上游未返回的用量保持 unknown，阈值根据实测校准，不为跑绿放宽标准。

- 保留问题闭环、共享知识审核/权限与现行留存规则；源码 24 小时上限不能套用为会话、成绩或问题表的留存时间。

## 7. 2026-09-21 决策更新（恢复身份与并发冻结）

用户对 §3「恢复身份与并发：幂等键与输入身份」三项拍板，B9/B10 修复与 S3 恢复设计的身份地基自此冻结：

- **输入身份**：`input_hash = sha256(原始问题全文 ‖ 附件文件名 ‖ sha256(附件字节))`，新增 `input_hash` 列；`question` 列继续存脱敏文本（**展示/存储口径与身份口径分离**——B9 的根因正是把脱敏存储格式错当身份判据），不脱敏原文不落库。归一化仅 Unicode NFC + 去首尾空白，不做语义折叠；同一 `request_id` + 不同 `input_hash` → 409 冲突（现有语义保留）。
- **任务身份分层**：`request_id` 为客户端幂等键（会话内唯一）；服务端受理时生成 `task_id` 落库，绑定 `(session_id, request_id, input_hash)`；恢复、查询、重放均按 `task_id`。
- **同会话并行**：允许。`request_id` 天然区分任务，不引入「会话内串行」不变式；S3 按 `task_id` 精确接续。

影响批次：S2（B9/B10 按此口径修复，`input_hash` 列的 alembic 迁移随 S2 提交）、S3（任务持久化与恢复围绕 `task_id` 设计）。至此 S2 的全部前置决策（B2 引用口径、B14 会话内锁 release、本节身份三项）已齐。§3 其余项（恢复时权限、临时源码细节、任务结果未知、展示与重连、预算与容量、学习辅助政策）仍为 S3 前置待决。

## 10. 2026-09-23 决策更新（S4-d 在线 judge 存留拍板）

用户按 S4-a 证据（`.logs/s4a_judge_eval_20260922/`，qwen3.8-flash 真实凭据、11 例标注题集）拍板：**维持离线口径**，`RAG_ONLINE_JUDGE_ENABLED` 保持默认 `false`，§9 待决项就此落定。

证据要点：

- 清晰例判准：supported / partial / insufficient_evidence / conflicting_evidence 四例全对；
- 边界例系统性偏严：`needs_clarification`（"那个配置怎么改？"）与 `not_applicable`（"你好"）均被判 `unanswered/insufficient_evidence`——在线启用会把正常澄清/闲聊回答误降级；
- 延迟与长尾：单次核验 5–11s，首轮 2 例撞 30s 超时呈现 `system_error`（timeout=90 复跑 6.6s/11.1s 判对，属端点抖动）；在线启用需上调超时预算，否则长尾转化为用户可见错误；
- 成本：11 例共 3075 tokens，逐请求核验代价可量化但不低。

维持离线的理由：确定性四判据已兜住机械性失败（空答案/引用越界/无证据/缺引用）；边界偏严会误伤正常回答；长尾超时直接变成用户可见 `system_error`。若未来重议在线核验，前置条件：judge prompt 修订 `needs_clarification`/`not_applicable` 口径、超时预算上调、扩题集复测——离线验收链路（`scripts/rag_judge_eval.py` + `tests/rag_eval/judge_cases.yml`）保留可用。
