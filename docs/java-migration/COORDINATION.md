# 多Agent协作与上下文控制

## 角色

- 主Agent：维护目标/当前授权/依赖/所有权；派工；审查交付证据；集成与阶段验收；写短状态和主交接。
- 实现worker：只执行一张卡或一个明确子卡，拥有指定文件；做必要测试并落盘证据。
- 验证worker：读实现，独立验证契约和场景；不在验证任务中顺手改业务代码。
- 集成worker：按主Agent委派独占公共文件窗口，实现接口/配置/DDL变更；报告影响与回归。

建议主+最多3名并行worker。可用槽少时顺序执行；并行数是上限不是目标。一次分派同时写清工作区、目标、允许路径、只读路径、契约版本、验收、证据位置与停止条件。

## 保持主Agent上下文简洁

1. 主Agent每轮先读STATUS、当前任务卡摘要及最新 `handoffs/MAIN.md`，初始热上下文目标约150行以内；设计与源码按需读。
2. 子任务使用新上下文；传递任务ID和文档路径、当前授权，不复制完整对话。若系统不支持独立上下文，人工新建会话也使用同一包。
3. 子Agent每次回报最多500字：结果、变更文件、实际验证、阻塞、证据链接。完整命令、日志、trace留在文件。
4. 主Agent以检索定位源码/证据，先看摘要和断言；不把全文件或全日志贴进上下文。
5. 每次任务收口或关键决策后更新STATUS；每阶段结束、准备换主Agent/上下文压缩前更新MAIN handoff。
6. 若连续两轮重复定位同一事实、混淆版本/owner或大量历史挤占任务判断，先写恢复点再换新上下文。文档不能强制模型清空上下文，也不依赖特定产品命令。
7. 新主Agent从文件恢复，核对工作区和Git状态，确认仍运行worker及文件锁；无需重读全部历史聊天。

`MAIN.md`建议不超过100行，只保留：目标、授权、基线/构建、当前阶段、在跑任务/owner、阻塞/决策、最近验收、下一步。旧内容归档为带日期的main handoff，不层层追加到热入口。

## 文件所有权

| 文件组 | 所有者 | 规则 |
|---|---|---|
| STATUS、阶段放行、MAIN handoff | 主Agent | worker只报告不改状态 |
| SCOPE/PLAN/DECISIONS | 主Agent | 设计worker提交建议，由主确认范围与授权后更新 |
| migration/contracts | J0-01指定的集成者 | 公共契约版本化；改动列消费者/回归 |
| migration/fixtures、oracle | J0-02 owner | 黄金数据不可由实现结果反向覆盖 |
| 根pom/wrapper、共享配置、contracts/platform、DDL | 集成worker | 单写窗口、串行编号、明确事务与版本影响 |
| feature包及同形测试 | 当前任务卡owner | 仅改授权路径；邻近文件发现问题先报告 |
| frontend客户端/main、nginx、Compose、CI | 集成worker | 按阶段串行接线，worker给patch建议 |
| 单卡handoff与evidence | 该卡owner | 后续审查追加独立review文件，不覆盖原证据 |

`chat/**`：J1-04完成后owner释放，P3顺序转给J3-03；禁止两卡同时修改。其他顺序接线也在STATUS owner栏登记。
task通过session/usage公开事务参与接口；不得复制其仓储。跨卡测试归集成卡/验证卡，业务缺陷交回原owner。

## 工作区与集成

当前副本已初始化Git并关联用户新建远程，用户已授权首次基线提交与推送。后续推荐每个worker独立分支/工作树，分支名 `codex/jX-YY-short-name`。不假定工具自动创建或隔离，主Agent派工时明确绝对路径并核对。

若仍共享一个目录：严格不重叠写入；相互依赖的修改串行完成；禁止worker运行reset/clean或回滚他人文件。独立工作树仍需公共接口版本同步，不能靠隔离掩盖契约冲突。

集成顺序：worker交付→独立审查→集成者对照白名单diff与秘密/运行产物检查→集成到阶段分支→针对依赖运行必要回归→状态更新。
提交/推送按用户在新仓库的授权执行；规划模板不自动授权远程写入。阶段完成前不把未验收变化发布到旧部署。

## 状态和完成语义

任务状态：`planned → ready → running → review → accepted`；阻塞用`blocked`并记录原因/解除条件。部分跨阶段接线用`integration_pending`，不能写成全部验收通过。

每个任务另列四个维度：实现、自动验证、场景验收、用户验收。用户通常验收阶段，无需逐卡确认；主Agent可在已授权阶段内接收有证据的任务交付。
阶段门禁只允许PLAN预先列明的接线项延期；P5不得残留未解释的强制项。跳过、未授权、环境不可用均不计通过。

接口改变先写：问题/必要性、原/新契约、影响任务、兼容策略、补验范围、是否改变用户范围。影响多个owner时暂停依赖任务，主Agent协调一次性更新。

## 任务拆分与长时恢复

- 单卡过大时按可验收行为拆 `J2-05a` 等子卡；父卡保留总验收，STATUS登记子卡和owner。禁止只按任意代码行数拆。
- worker中断前写自己的handoff，包含未提交文件、测试退出码、未结束进程/端口/容器、下一步。没有可用证据时明确“未验证”。
- 主Agent换会话前记录在跑任务是否仍可能写文件；先停止或确认所有权交接，不能两个主Agent同时调度。
- 恢复后先检查快照/构建/fixture是否匹配；旧测试只证明旧提交，不复用为新代码自动通过。
- 原始日志留在被ignore的 `.migration-artifacts/`；可提交 evidence只保留合成数据、脱敏摘要、断言和必要截图，不包含真实源码/令牌。

## 统一交接模板

worker用 `templates/HANDOFF.md`，独立验证用 `templates/REVIEW.md`，主Agent用 `handoffs/MAIN.md`。
当前所有文档仅是协作协议，不是已安装的调度系统、自动持续运行服务或可用CLI的证明。
