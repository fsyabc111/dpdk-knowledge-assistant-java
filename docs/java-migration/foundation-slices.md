# 基础、运维与收口任务卡

路径相对新仓库。未创建的命令、目录与测试名是交付要求，不是已可运行事实。每卡另拥有自己的 `docs/java-migration/evidence/<ID>/` 与 `handoffs/<ID>.md`。

## J0-01：冻结源码、接口、schema与迁移决策

- 目标：为后续所有任务建立唯一行为与数据基线，先解决“和什么一致”。
- 依赖：COPY_REPORT校验通过，用户放行P0。若副本已有后续变化，记录新快照而不覆盖原manifest。
- 两步里程碑：先交付源码/路由/schema/接口/隔离规则的“初版可消费”，解除J0-02依赖；J0-02产出oracle与合成基线后，本卡收录阈值/差异形成“最终冻结”，才申请P0验收。
- 阅读：COPY_REPORT、SCOPE、DECISIONS；按模块读 `backend/app/api/`、schemas、config、storage DDL和alembic；旧docs只作线索。
- 独占可写：`migration/contracts/**`、`migration/baseline/**`；本阶段经主Agent委派可更新ARCHITECTURE/DECISIONS，STATUS仍主Agent所有。
- 产物：全量路由（含内部隐藏端点）清单、JSON/SSE错误/字段契约、schema清单、配置映射、外部依赖清单、模块接口草案、兼容差异账本。
- 明确 source HEAD+dirty manifest 与未来部署镜像/schema起点分离。新副本只使用其冻结Python快照做oracle，不随源仓库自动同步。
- 身份样例：NFC、Python strip语义、JSON转义/空格、UTF-8、附件原件hash与执行源码hash；bcrypt、token摘要、时区/精度/空值。
- 并发样例：受理原子性、账号停用/成绩竞争、答案/引用/终态事务、任务认领、索引CAS；明确没有fencing保证和正式提交无业务幂等键。
- 迁移策略：给出空库、合成0013库、等价0015库路径；指定唯一迁移owner；基于完整schema核对后再登记baseline。
- 阈值：与J0-02一起制定可量化质量/容量/恢复指标；基线尚未实测的数字先标待测，P0验收前由用户确认。
- 非目标：Java业务实现、生产探测/迁移、改旧Python、运行现有部署入口、复制真实业务库。
- 验收：每条实际路由恰有责任卡；每张生产表/关键配置有Java去向；关键接口字段和事务所有权明确；待决项有阻断阶段；文档冲突已分类。
- 验证方式：静态路由/表/配置清单自动枚举并与契约对照；不通过导入app触发真实配置/数据库初始化。脚本与命令由本卡实现并记录。
- 证据：清单覆盖报告、源路径/行号、manifest ID、决策确认记录及差异处理表。
- 回退：撤回新增契约版本，不改复制基线；依赖卡尚未实现。

## J1-01：Java基础、隔离测试PG与公共契约

- 目标：提供可构建、可隔离启动、可失败退出的Java骨架与公共基础；支持其余卡独立开发。
- 依赖：P0用户验收；版本组合/迁移方案决策明确。
- 独占可写：`backend-java/pom.xml`、Maven wrapper、根配置、`platform/**`、`contracts/**`、共享测试设施、`backend-java/src/main/resources/db/**`、`migration/environment/**`；同形test路径。
- 集成者角色：本卡worker在授权窗口承担共享文件owner；后续业务卡通过接口变更申请请求修改，不直接写公共代码。
- 交付：Java21候选的实际依赖构建验证、BOM/锁定版本、配置模板和校验、公共DTO/端口、错误映射、受控时钟、事务参与、健康和日志基础。
- 提供测试PG安全预检：显式测试标记/独立DB身份、独立容器/网络/卷、禁用ambient配置；未设置时失败或明确skip，绝不静默使用旧库。
- 提供不依赖真实模型/MCP的纯单元和PG集成入口；默认测试死上游或本地替身；快测与集成测分别命名。
- 迁移：由唯一owner实现经过清单校验的空库baseline与升级链；fixture包含表、约束、版本和业务读取检查；禁止Hibernate自动修改旧schema。
- 初期数据库方言只面向PG，旧SQLite测试保留作参考；如引入其他测试替身必须明确不能证明PG并发语义。
- 非目标：完成账号/RAG业务、提前引入Redis/消息队列/微服务、连接生产、下载旧镜像升级部署。
- 验收：干净环境构建成功；配置错误fail-closed；无凭据启动测试profile；独立PG迁移可重复；对危险数据库目标的负例确实拒绝；日志不输出秘密。
- 命令交付：`./backend-java/mvnw -f backend-java/pom.xml verify` 及独立PG预检/集成profile的确切命令；所有占位在hand-off中替换为实际参数名。
- 证据：依赖版本、JDK输出、构建退出码、空库/0013合成库/等价0015读写测试、错误目标拒绝测试和资源清单。
- 回退：停止本卡创建的独立资源、撤销骨架提交；保留source baseline与证据。资源清理必须按精确项目名，不能全局prune。

## J4-03：运维CLI、监控与可交付部署物料

- 目标：让Java版本具备日常可运维能力，并提供P5可验证的独立部署/CI入口。
- 依赖：P3验收；索引CLI与知识留存最终接线需J4-01/02。基础指标可先按冻结端口工作。
- 阅读：`backend/app/main.py`、`backend/scripts/`、`core/metrics.py`、deploy脚本与现有CI；先枚举用途再映射。
- 独占可写：`backend-java/.../operations/**`及测试、`deploy-java/**`、`scripts-java/**`、`docker-compose.java.yml`、新Java CI文件；根配置/前端/共享pom由本卡集成者窗口串行修改。
- 交付CLI映射：用户创建、会话清理、问题/输入留存、索引ingest/rollback、离线judge/检索验收；Python旧迁库一次性脚本明确保留或退役，不静默遗漏。
- 健康：health/ready区分；就绪核对物理节点/指纹；结构化事件与用量unknown规则保留；指标兼容映射写清，不假设自动指标同名。
- 保留/清理：默认dry-run、显式apply、源输入终态清理和TTL兜底；备份排除临时执行输入，恢复过程仍可维持业务数据完整。
- 部署：全新project名、端口/卷/网络/数据库，不沿用`dpdk-assistant`；外部源显式只读路径，不用新目录`..`猜位置。
- 安全：HTTPS/SSE、仅API反代、metrics内网、harness专网/非root/只读/tmpfs/资源限制；配置模板和证书生成脚本不含真实秘密。
- CI：纯单测/PG集成/前端test+build分层；默认CI不调用真实模型/评测；失效的旧Gitee部署触发需明确停用或隔离。
- 非目标：实际生产切换、多副本扩容、盲目安装代理/镜像、把本地路径硬编码到新仓库。
- 验收：CLI帮助/参数/失败退出；dry-run无写；明确fixture上apply结果正确；就绪负例；Compose展开与网络拓扑检查；备份恢复由J5-03实证。
- 证据：CLI清单覆盖、日志/指标映射、脚本命令、配置风险检查和隔离部署清单。静态Compose检查不等于已部署。
- 回退：撤销新物料/CLI，保留旧参考；不修改现有部署与入口。

## J5-04：最终交接、受控切换与Python主后端退役

- 目标：给用户一个明确可接手的Java交付，并在获得独立授权后完成指定环境切换。
- 依赖：J5-01/02/03证据、用户验收、精确版本/环境和待决风险。生产切换与删除资产是不同授权。
- 独占可写：新README、迁移状态/最终交接/运维索引及经批准的部署开关；原仓库默认只读。
- 先交付：Java构建/源码ID、schema/fixture/模型/知识版本、部署/回退手册、依赖许可证、已知限制、用户验收记录和维护责任。
- 若用户暂不切旧部署：交付独立Java仓库即可；状态写“新仓库已交付，生产切换未授权/未执行”，不能把未执行切换写完成。
- 获准切换后：备份并实际验证恢复→停止接收新写入→排空/登记在途任务→确认单一执行/迁移owner→运行经演练步骤→业务检查→监测窗口。
- 回退条件：按J5-03手册；新数据存在时先判断旧应用可读性，不能用旧备份覆盖增量。不可向后兼容时停止写入并执行批准的数据处理路径。
- Python退役：先停主后端运行依赖，再处理参考代码/工具保留策略；harness保留Python属于已定范围。删除旧仓库/镜像/备份须用户明确授权，不能作为自动清理。
- 非目标：自动创建远程/推送、将规划当生产授权、取消未验证项、删除恢复资产。
- 验收：用户可按新README独立运行测试环境；交付包完整；如执行切换则有真实目标、步骤、检查/观察和回退证据。
- 证据：最终矩阵、用户接受的限制、现场版本、单写owner和回退条件；“交付”“切换”“退役”分三项记录。
- 回退：交付文档可撤回；运行操作只按实测手册；无法保证数据保全时不继续破坏性恢复。
