# Java 迁移范围

## 目标

以现有 DPDK 教学助手的业务行为为基线，将在线主后端、Agent/检索编排和知识索引维护迁到 Java；现有 React 前端可通过同一接口继续完成教学闭环。迁移在独立工作区、独立测试数据和独立部署环境中验证。

这是重写与兼容工程，不保证 Python 类/文件和 Java 类逐一对应。优先保留对外行为与数据身份，内部按功能模块重新组织。

## 建议迁移基线

- 源码：复制时的 `a47a1bc9d23c0a8e625a79ff7cfbd096dcb3071c` 加工作区未提交与未跟踪源码/文档；逐文件摘要见 `baseline-manifest.json`。
- 当前部署文档说明仍使用旧镜像/schema0013；本轮未检查容器运行事实。
- 推荐 Java 功能目标对齐源码基线，旧部署数据是否迁入及怎样从0013升级另走P0设计与P5授权。
- 工作区已有的新改动属于复制内容，不代表这些改动已经验收。历史测试数字不是新仓库的验证证据。

## 纳入

1. 认证三模式、账号班级树、配额、停号/删除/审计、改密与用量查询。
2. 作业CRUD、协议与分值、提交评测、成绩/CSV、结果讲解；保留聊天评测与正式成绩分离。
3. 会话、附件、任务登记、重放、SSE、断线续跑、显式取消、重启重驱动、心跳与认领。
4. Agent五工具、轮数/token预算、上下文修剪、教学画像和参考实现、降级、用量记录。
5. 固定release的多路检索、RRF/代码启发式/MMR、引用绑定、历史节点读取。
6. 知识源切块、嵌入、增量比对、原子发布/回滚、健康检查、问题闭环和共享知识。
7. 生产PG数据结构兼容、迁移机制、隔离部署、观测/备份/清理、离线验收工具与CI。
8. 旧接口的错误状态码、空值、字段名、分页、时间、CSV与SSE等细节；差异必须登记并批准。

## 保留与非目标

- React、PostgreSQL/pgvector/zhparser 和独立 teaching_harness 保留。harness 的 Python 服务及运行的 C 插件不属于本次 Java 重写。
- 原 DPDK 主仓库与 harness 是外部依赖，不把它们的全部源码复制进新仓库；已有知识资料中的局部快照随源工作区保留，不能替代完整依赖。
- 首轮不换模型、embedding、切块算法或排序权重，不以迁移名义重建生产索引。
- 保持模块化单体和单副本部署口径，不追加微服务、Redis、Kafka、分布式队列或原生镜像目标。
- 不把普通账号token顺带改为JWT，不重设计权限/作业计分，不增加课程选课模型。
- 不承诺正式提交具有现有聊天任务同等的幂等/恢复能力。改进该能力需单独记录范围和验收。
- 不顺手修已知Python问题。安全或正确性问题登记为兼容差异，明确保留、修复或阻止切换；严重问题不能为了“完全一致”静默带入。
- Python 测试/离线参考工具可在过渡期保留。最终 Java 运行与日常维护不依赖 Python 主后端；独立 harness 是明确例外。

## 总完成条件

- 路由清单中的每个接口均被映射至 Java 实现、批准的兼容适配或明确退役决定，无隐式遗漏。
- 关键确定性行为差分样例100%通过，权限越界/重复扣费/错误引用/重复落成绩等阻断项为零。
- 模型输出以事实、引用和工具行为验收，不要求自然语言逐字相等；固定向量排序容差与合成性能/恢复阈值在P0冻结；依赖真实模型/embedding的质量数值在另获授权的live子批次先测Python基线，再于Java质量对照前冻结。
- 纯单测、独立PG集成、合成端到端、真实模型与harness场景的证据分开；未授权或未执行标为未验证。
- 断线、恢复、取消、重复请求、外部调用结果未知、数据库失败和队列饱和均有可复现证据。
- 用户在新环境验收教学闭环；切换前完成恢复演练、旧数据兼容判定和回退条件检查。
- Python 主后端退役需用户独立授权；旧仓库、旧部署、备份和外部依赖不由迁移 Agent 自行删除。

## 规划尺度

22个切片，每个应形成可独立审查的交付。若某卡预计超过1–3个专注工作日，主Agent在该卡内部再拆子卡（继承范围/验收/owner），不扩大阶段。
这是切片尺度建议而非总工期承诺。P1完成后用实际构建、差分和检索验证耗时再估算后续工期；AI生成代码量不作为完成比例。
