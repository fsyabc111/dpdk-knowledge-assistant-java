## 必要修订

### R1：将任务卡的源码阅读入口统一到冻结副本（P0前修）

- 位置：`ai-slices.md:6`明确“以下源入口均相对”原目录；`business-slices.md:6-9`同时列原目录和“源快照”，容易继续读取正在变化的原工作区。
- 冲突：`foundation-slices.md` J0-01要求“新副本只使用其冻结Python快照做oracle，不随源仓库自动同步”。
- 影响：长时迁移过程中原仓库新增修复，worker可能拿新源码实现、拿旧fixture验收，造成无法解释的契约差异；只读并不能防止此类漂移。
- 修订：统一声明所有Python实现/测试阅读路径为新仓库中的冻结`backend/`和对应冻结文档；原绝对路径仅记来源身份。
- 原工作区只能用于明确授权的差异调查；发现差异提交主agent决定是否创建新基线，不自行吸收。
- P0核对manifest，P1以后每卡启动只核对所需文件与冻结ID，避免按当前原仓库内容重新推导契约。

### R2：明确J0-01/J0-02的两步冻结，避免阈值门禁互等（P0派工前修）

- 位置：`PLAN.md:23,51`要求J0-01“冻结输出”后才运行J0-02；`foundation-slices.md` J0-01又要求与J0-02共同制定实测阈值。
- 影响：若把J0-01“完成/冻结”理解为包括全部容量/质量阈值，J0-02无法先测基线，J0-01也无法完成其阈值交付。
- 修订：拆为J0-01a冻结源码/路由/schema/接口/隔离规则→J0-02生成oracle并测合成基线→J0-01集成者收录阈值与差异→P0最终冻结。
- 不必增加顶层卡数，可在J0-01记录“初版可消费/最终冻结”两个里程碑；PLAN和完成条件用同一名称。
- J0-02尚无Java候选时，明确使用Python自对照及故意破坏的响应/副作用样例验证差分器正反例；不得等P1 Java实现才验收P0。

### R3：分开P0合成阈值与须真实调用的质量阈值（P0验收前修）

- 位置：`SCOPE.md:42`笼统要求“检索指标与性能阈值在P0冻结”；`DECISIONS.md`真实题库允许差值要基线实测；`PROMPTS.md` P0明确禁止真实模型/embedding。
- 影响：实施者可能把真实题库指标当P0必测而越权调用，或者为了P0通过凭空设真实质量阈值；也可能因未获live授权无期限阻塞实现。
- 修订：P0冻结固定向量排序容差、合成性能/恢复阈值，以及真实质量验收的题集/方法/预算决策流程。
- 真正依赖真实embedding/模型的数值，只能在明确授权的live子批次测得并于Java质量对照前冻结；在STATUS列为该子批次阻断项，不阻断合成P1。
- 若用户坚持全部质量数值P0定案，应明确把真实调用及预算作为P0新增授权选项；不能从“授权P0”自行推断已授权。
