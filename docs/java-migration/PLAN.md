本计划包含P0–P5六阶段、22张任务卡。状态仅在 `STATUS.md` 维护。下表描述目标和门禁，不表示已经实现或获准执行。

## 并行批次建议

最多主Agent+3个子Agent。只有互不改同一文件且公共接口已冻结的任务并行；不为了满员创建无价值工作。

1. P0：J0-01先交付“初版可消费”（源码/路由/schema/接口/隔离规则）→J0-02制作oracle与测合成基线→J0-01收录阈值/差异形成“最终冻结”→P0验收。不新增顶层卡。可并行只读盘点，写入仍按owner串行。
2. P1：J1-01先完成；J1-02与J1-03并行，检索先使用冻结embedding替身；J1-04集成。
3. P2：J2-01→J2-02；再并行J2-03与J2-05；完成接口后J2-04。剩余槽做已交付卡的独立审查。
4. P3：J3-01与J3-02可并行，依靠冻结端口/替身；J3-03集成→J3-04。以真实依赖集成关闭所有stub待接线。
5. P4：J4-01与J4-02可并行；J4-03可先做独立物料，CLI装配与就绪语义在前两卡后完成。
6. P5：J5-01闭环后进行J5-02，J5-03使用固定构建；J5-04先形成交付包，实际切换待明确批准。

公共文件由集成者独占并不意味着主Agent必须逐行编码：可以指派一个临时“集成worker”拥有该批共享文件，主Agent仅审查接口与证据。在其完成前其他worker不得写这些文件。

## 跨阶段接线与避免循环

- P1 synthetic问答不实现完整持久身份；持久会话/配额在J2-05，任务在J3-01。
- J2-02停号任务取消、J2-05活动会话删除的执行中任务处理，在P2以冻结端口测试并记录 `integration_pending`，P3必须用真实task实现补验。P2不得声称这些组合场景已通过。
- J2-04正式提交不依赖聊天任务框架，沿原同步契约；其quota仓储由J2-05提供，避免依赖J3。
- J3-01编排受理事务，session/usage仓储参加同一事务；跨模块集成测试由J3-03和集成者承接，原owner补实现。
- J4-02知识发布记录与J4-01索引实际生效分开测试；最后用一条端到端路径证明连接完成。
- P5只验证与报告缺陷，修复归原实现卡，不在验收分支复制业务逻辑。

## 阶段报告固定结构

本阶段目标与构建ID → 完成切片 → 自动验证 → 场景验收 → 未验证/允许延后项 → 重大差异/回退条件 → 请求用户验收与下一阶段授权。
完整报告落 `evidence/Px/phase-report.md`，主Agent面向用户只报结果、阻塞和待决点。没有足够证据时保持未验收，不通过调整阈值制造完成。
