## 5. PG、迁移链与数据语义

Java默认集应隔离上游与数据库；单元测试可不用DB，持久化集用临时专用PG17+pgvector。
不以H2/SQLite替代PG的锁、JSONB、唯一约束、时间类型、事务和pgvector/FTS语义。
PG容器/实例可采用Testcontainers或隔离Compose，具体方案由基础设施卡冻结。
测试配置不得自动加载复制前后的`.env`，显式拒绝非测试库及生产Docker context。
Python的`live/postgres` mark豁免隔离不直接照搬到Java；PG测试仍默认死上游或本地替身。
数据库迁移只有一个owner：由主agent在J1-01基础设施卡中指定并登记姓名/agent ID。
所有业务卡只提交DDL需求与契约；迁移文件编号、基线DDL及升级链由该owner统一写入。
J5只读迁移实现并执行已授权演练，不另造第二套DDL或自动修库脚本。
覆盖空库建表、完整旧schema0013升级、当前0015等价库加载和重复启动幂等四条路径。
0013与0015测试库由合成fixture生成；不能因“克隆”名义复制真实账号、会话或成绩。
验证表/索引/约束、历史NULL输入hash、旧任务/成绩关联、讲解purpose及历史引用兼容。
旧bcrypt密码、token格式、时间/时区、字符串归一化、精度、CSV编码须用合成向量核对。
事务故障点覆盖受理写入、成绩+job提交、答案+引用+终态、CAS发布和回滚失败。
SQL结果必须比较业务意义与约束，不能只比较行数或“migration exit 0”。
Flyway/Liquibase/自有版本表与Alembic共存策略在P0决定；禁止两迁移器同时自动升同一库。
默认采用扩展兼容变更；删列/改语义等破坏性DDL不得混入功能移植验收。

## 6. 模型非确定性与检索对照

阶段A：固定上游脚本验证编排与协议，属于自动门禁；两端应可复现等价状态和副作用。
阶段B：固定语料、release、向量和题库比较召回列表、RRF/MMR、must_top及引用映射。
阶段C：获真实调用授权后，用冻结模型/提示词/参数/知识版本进行质量对照。
真实模型不以逐字答案相同为通过，也不以一次更漂亮的回答掩盖回归。
既有`product_acceptance.yml`要求教师复核，不能直接把全部100个候选题称为黄金标注。
P0逐题审核证据位置、预期类别和关键事实；未经审核题目只能观察，不参与硬阈值。
使用配对题集、两端随机交错顺序、每题至少3次；盲评关键事实/引用/拒答/教学政策。
保存每次失败与分布；禁止只展示最好一次、删除超时或用重新抽样替换失败。
检索recall@1/5/15、MRR、must_top与回答质量分别报告；judge另列，不代替人工oracle。
真实模型评测中的`grade_plugin`必须替身化；真实harness副作用试验另立互斥执行窗口。
不将同一个真实MCP提交同时镜像给Python与Java，不以双跑证明幂等。
线上judge默认false保持；原题verify显式judge路径单独覆盖，不因默认关闭漏测。
预算、重复次数、标注集规模、评判方法及制定允许差异的流程在真实调用前确认；先在获准live子批次测Python质量基线，再冻结允许差异数值，之后才能做Java质量对照。
无真实调用授权时可完成替身验收，但报告须保留“真实模型/embedding质量未验证”。

- 故障点：受理前/后、模型返回前/后、MCP提交前/后、成绩事务前/后、终态保存后连接断开。
- 断线不取消；显式取消可重入；页面刷新找回；完成任务重放不再次调用上游。
- 后端kill/restart后先查job；finished复用，running等待，unknown按冻结恢复策略处理。
- MCP提交结果未知时不得盲目重试；先查状态并确认旧执行归属/终止，再按同job身份处理。
- 重启丢失harness内存账本是独立场景；真实harness验证待另授权，替身结果不能代替。
- 账号停用取消pending且不落未完成成绩；作业改名/撤回/改分/过期按现有受理快照规则。
- 合成时钟推进验证冻结实际配置的任务硬时限（当前源码默认10分钟）、24小时输入兜底、终态即清、重放TTL等边界。
- 单副本为生产目标；双副本只测已有属主心跳/认领防线，不承诺共享admission或全局扩容。
- P0负载规模沿用已定≤60学生、峰值≤10问答；另覆盖20活动/20等待边界及队列超时。
- P0建立固定mix：60合成账号登录/看作业；10并发问答；提交与讲解独立分组计量。
- P0登记CPU/内存、PG镜像、数据规模、替身延迟/失败脚本、预热与测量时长。
- 建议采样每端3轮：预热2分钟、测量10分钟；同时报p50/p95/p99、错误率、排队与资源峰值。
- 先测Python基线，再由主agent提交绝对p95上限、允许差值、错误率、CPU/RSS和恢复RTO数字。
- 这些数值须P0用户确认后冻结；未定不能以“性能不下降”代替，也不能宣称容量通过。
- 正确性硬阈值为零越权/重复业务扣费/重复聊天成绩/永不终态任务；上游费用unknown单列。
- 统计样本不足不计算伪精确p99；超时与拒绝计入总请求分母，区分预期背压和异常。
- 验收：故障矩阵全通过，状态/副作用与oracle一致，冻结容量阈值达标且无未解释尾部异常。
- 证据：故障时间线、替身账本、PG前后快照断言、资源曲线、全部轮次原始统计与恢复耗时。
- 回退：撤销故障注入和测试资源；失败回退上一构建继续分析，不降低阈值。

## 9. J5-03：隔离部署与回退演练（P5）

- 目标：在完全隔离环境证明可部署、可迁移、可恢复；实际生产切换仍是另行批准的动作。
- 依赖：J5-01/02通过；迁移owner冻结包；外部依赖契约；获准隔离部署/恢复演练范围。
- 独占可写：`acceptance/deployment/**`、`docs/java-migration/evidence/J5-03/**`、`docs/java-migration/cutover-runbook.md`。
- 非目标：不切真实入口、不读写生产库、不启动真实评测、不升级旧镜像、不退役Python。
- 隔离栈使用独立项目名/端口/卷/库/网络；测试前记录目标，拒绝生产context和原命名。
- DPDK知识源使用合成副本；harness使用本地替身，依赖缺失要明确报错而非静默少索引。
- 验证nginx静态资源、HTTPS/SSE、只反代/api、健康就绪和harness网络隔离设计。
- 演练schema0013合成库→迁移→Java读写→备份→恢复到另一空库→业务断言。
- 回退首选应用镜像回退与向后兼容schema；不得假定数据库downgrade一定无损。
- 切换手册必须列旧/新构建ID、schema兼容范围、入口开关、所有权和每步验收点。
- 真实切换前停止新写入并排空/登记活动任务，确保同一业务只由一个后端执行。
- 交接期不得让两后端同时恢复同一任务或自动迁移同一数据库。
- 回退触发列明：权限/数据错误、恢复失败、冻结容量门禁失败、ready失败及超时未完成。
- Java产生新数据后必须证明旧镜像可读；否则冻结写入后采用已演练的数据前向修复或独立恢复。
- 恢复旧备份会丢失切换后数据，需先保存增量并由用户确认处理方案，不得静默覆盖。
- P0确定演练RTO/RPO；生产RPO与停机窗口在真实切换授权前单独确认。
- 验收：隔离环境冷启动、升级、备份实际恢复及应用回退均有业务断言；未读写原环境。
- 证据：部署清单、迁移日志、备份摘要、恢复库校验、切回记录及RTO/RPO实测。
- 回退：停止并清理已确认的隔离资源，保留证据；实际生产无改动无需回退。
- J5-04退役由主agent负责；本卡通过不授权删除旧Python、镜像、备份或运行入口。
