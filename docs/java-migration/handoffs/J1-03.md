## 决策与接口差异

### 冻结 Python golden 驱动（非手工期望）

所有阶段期望值由**冻结源码本体**生成：stub 重依赖后导入真实 `app.services.retrieval_service`（oracle 脚本存证据目录），SQL 腿在真实 PG 上按 `li_retrieval_store` 原句提取后冻结。Java 实测与 golden 逐项一致（排序精确、分数 1e-12，实测差值 0）。生成链可复现（evidence/J1-03/README.md）。

### 契约缺口（最小变更请求，请集成者裁定；当前占位契约可用）

1. `contracts/retrieval/SearchInput`：建议增加 `String rewrittenText`（调用方预改写时跳过内部改写）、`String conversationContext`（追问消解）、`int limit`（现为默认 6；本实现已提供重载 `searchPinned(snapshot,input,limit)`）。
2. `contracts/retrieval/RetrievedChunk`：建议增加 `sourcePath/section/title/metadata`——J1-04 引用与引用展开必需；当前富字段经 `RetrievalTrace.nodes`（trace 为 Object）交付。
3. `contracts/retrieval/SourceChunk`：建议增加 `title`（legacy 回读的 documents.title 回退逻辑已实现于 `PgReleaseReader.legacyChunk` 富读取器）。
4. `contracts/retrieval/ReleaseSnapshot`：建议增加可选 `blockedReason`/成员完整性字段（Python release_health 的 declared/members/physical）；当前失配原因只在 trace。

### 行为差异（已登记 evidence/J1-03/differences.md）

filename_boost 的多文件名 set 序 nondeterminism（Java 取 findall 序，确定性更严格）、向量字面量指数格式（不影响 PG 解析/排序）、配置失配不粘实例（每次重核，方向更严格）、TTL 缓存与用量账本未实现（J1-02 装配）、fetch_rows 无 ORDER BY（与源逐字一致）、Unicode 边缘码位理论差异。
