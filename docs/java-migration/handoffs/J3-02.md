## 决策与接口差异

1. **接口变更请求（请集成者登记/裁决，非阻塞本卡）**：
   - `contracts/grading` 缺 `TaskGradeParticipant` 的 Java 接口（契约 JSON 只有枚举与 record）。我方在 `agent/port/TaskGradePort.java` 按冻结签名 `TaskGradeResult recordTaskGrade(TaskGradeInput)` 建消费侧接口；集成期请正式化到 contracts 或由 J2-04 提供实现。
   - `rag_task_jobs` 账本（findJob/recordJob/reserveGradingJob/finishJob/updateTaskSource）未冻结 Java 端口，`agent/port/TaskJobLedgerPort.java` 为轻量替身接口；J3-01 落地时以其仓储实现替换（签名对位 rag_issue_service 同名方法）。
   - `contracts/model.ChatInput(model, jsonPayload)` 为 role/content 形态，不含 tool_calls/usage/多消息结构；Agent 用 `agent/AgentChatModel` 作替身边界。集成期需要富接口适配（J1-02 handoff 已提出 `chat(List<ChatMessage>,...)`；建议一并补 tool-calling 形态）。
2. **行为差异（有意，待集成复核）**：
   - 无效 UTF-8 字节：Python `errors="replace"` 产出 U+FFFD；Java `String.getBytes(UTF_8)` 对孤立代理项产出 `?`（0x3F）。所有输入先经 JSON/multipart 解码为 String（替换语义一致），差异仅限合法 UTF-8 不可能产生的孤立代理项，实际不可达；登记备查。
   - `splitlines` 完整覆盖 Python 的行界集合（\v/\f/\x1c-\x1e/\x85/\u2028/\u2029）。
   - `get_reference_answer` 的 harness 调用期限取固定 120s（Python 走客户端默认超时）；`get_task_status` 仍为 min(grading_timeout,30)。
   - 非流式 delta 粒度为整条消息（脚本化模型无流式 chunk）；SSE 流式细化由 J3-03 的模型适配器承接（W9 口径已在 AgentChatModel.AgentReply 契约注释声明）。
3. **设计决策**：
   - 图不使用任何框架循环，planner/tools/finalize 全部受同一控制器约束（框架自动工具循环关闭的等价实现）。
   - sources 事件只交累计片段列表，Citation 装配（engine/rank）留给 J3-03 CitationBinder，避免越权实现其冻结契约。
   - 未知远端状态（探测失败/running）不虚构终态：统一以同 job_id 幂等重投（COMP-003 语义），与 J1-02「提交后禁止传输重试」严格区分——重投只发生在业务恢复路径且以账本行为锚。
   - 讲解模式预播种 `grading_results`（复用 harness 载荷形状）触发参考注入与降级评分事实，是有意复用非新评测。
