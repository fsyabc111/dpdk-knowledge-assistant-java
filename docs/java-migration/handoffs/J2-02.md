## 决策与接口差异

1. **消费 auth 的方式（接口变更请求，需 auth owner/集成者处理）**：
   - `PasswordRuleException` 非 public：AdminController 以“类名识别”把端口抛出的规则异常转
     400 detail（当前行为等价、文案逐字）；请求 public 化或端口化。
   - `UserAuthRepository.verifyCredentials`（删除授权密码校验，含 dummy 等价工作）未端口化：
     admin 依赖具体类（同一 Bean）；请求提升为端口方法。
   - PATCH roles/daily_quota 后 Python 会 clear_token_cache；auth 未暴露缓存清理 →
     差异：改配额/角色后最长 60s 内 resolve 缓存返回旧 Principal（token 有效性不变）。
     请求 auth 暴露 clearPrincipalCache() 或等价端口后由 AdminController 在 PATCH 成功后调用。
   - `PasswordResetApprovalPort.ResetRequestRow.createdAt` 为 isoformat（T 分隔）；HTTP 列表
     需 Python str(datetime)（空格分隔），J2-02 已做一次转换，请 J2-01 知悉（其 /api/auth 侧无影响）。
2. **班级范围端口**：`admin/AdminClassScopePort`（scopeCreator/studentIds/visibleSubjects，
   实现 AdminClassScopeQueries）。J2-03 作业、用量/问题工作台消费请走此端口；operator 在
   grading 视图的不受限规则属消费方角色门禁，不经端口表达。
3. **停号取消端口**：`admin/LocalTaskCancellationPort`（默认 NoOp 占位，integration_pending
   IP-1）；J3-01 接线真实执行体。库内级联（撤 token/取消 rag/删输入/删任务成绩）已在
   AdminUserRepository.setEnabled 单事务实现并验证。
4. **照源行为**（非差异，防误改）：assign 允许改已归属 viewer；删除路径不触碰 rag_requests；
   老师列表本人行在前；删除 leader 判定只认 actor.roles（静态 token 进不去）。
5. 已知差异：AdminPydanticBody 的 json_invalid 沿用 J2-01 NaN/Infinity 登记；非 golden 的
   pydantic 分支文案未逐字节比对（evidence/J2-02/golden-diff.md §3）。
