## 决策与接口差异

契约 `contracts/model/*` 文件未改（占位字段维持）。交付语义与请求登记：

1. **接口变更请求（请集成者在 transaction-ports.json/契约侧登记，非阻塞）**：
   - `ChatInput(model, jsonPayload)`：jsonPayload 约定为 `{"messages":[{role,content}...], "model"?:...}`；
     富接口为 `chat(List<ChatMessage>, model, ModelUsageLedger, stage)` 与
     `streamChat(...)`、`embedTexts(List<String>, ledger, stage)`。
   - `HarnessReply(submissionPhase, payloadJson, error)`：payloadJson 恒为规范化 JSON
     （成功=工具结果；失败=`{"ok":false,"error":...,"detail":...}`）；error=错误码或 null。
     新增错误码 `harness_bad_request`（参数不可序列化，NOT_SUBMITTED）与
     `harness_deadline_exceeded`（期限前到期，NOT_SUBMITTED）。
2. **行为差异（有意，详见 evidence/J1-02/unverified.md 表）**：参数序列化提前（NOT_SUBMITTED
   而非源实现的 UNKNOWN）；取消采用 shield 模型（不伪称远端已取消，账记 unknown，许可背景归还）；
   异常日志不回显 payload/源码哨兵（源会打印 payload[:500]）；embedding 非数字 index 按 0 排序。
3. **Jackson 2/3 并存坑（对集成者重要）**：classpath 同时有 `tools.jackson` 3.1.7 与
   `com.fasterxml` 2.21.7，RestClient 消息转换优先 Jackson 3，Jackson 2 `ObjectNode` 直接
   作为 body 会被按 POJO 展开。本切片 harness 请求体以 UTF-8 字节数组发送规避。后续模块
   若用 Jackson 2 树作为 RestClient body 需同样处理（或统一改用 Jackson 3 树）。
4. **无新增依赖申请**：全部用既有 classpath（spring-web RestClient、JDK HttpClient、Jackson、
   JUnit5/AssertJ、com.sun.net.httpserver）。
5. Spring Bean/配置接线（`ChatClientSettings` 等的 properties 绑定、`ModelClients` 单例装配）
   留给集成者，本切片只交付显式构造类。
