## 决策与接口差异

1. **contracts.identity.AuthSettings 字段补全请求（最小公共文件变更请求，请集成者裁决）**：
   契约 record 现为无字段占位（注释"字段由 J2-01 登记补全"），但 contracts/** 归集成者，
   本卡未改。`AuthPrincipalResolver.resolve(headers, settings)` 的第二参数当前被忽略，
   生效配置来自 auth 包 `AuthSettingsProvider`（生产从 Spring Environment 读 Python
   同名变量 AUTH_MODE/API_TOKENS_JSON/AUTH_TOKEN_TTL_DAYS/PASSWORD_MIN_LENGTH/
   BCRYPT_ROUNDS/LLM_DAILY_QUOTA_DEFAULT，启动期做 config.py 同款校验）。
   建议：AuthSettings 增加 authMode/staticTokens(或 apiTokensJson)/tokenTtlDays/
   passwordMinLength/bcryptRounds/llmDailyQuotaDefault 字段，resolver 改读参数；本卡
   单点替换即可，消费者（J2-02..J4-02）签名不变。
2. **resolve 失败语义**：resolve 以 `ApiDetailException(401, detail, WWW-Authenticate:Bearer)`
   抛出（Python require_auth 抛 HTTPException 的等价映射），未再定义独立受检异常。
3. **J2-02 协作端口（auth 包公开，J2-02 消费）**：`CredentialInvalidationPort`
   （resetPasswordToInitial/setPasswordByAdmin[抛 PasswordRuleException，detail 文案即 400 体]/
   revokeUserTokens）与 `PasswordResetApprovalPort`（listResetRequests[树隔离 scope]/
   approveResetRequest[返回一次性明文令牌+30min 过期]/rejectResetRequest）。admin HTTP
   层归 J2-02，本卡不建 /api/admin/*。
4. **行为差异（已登记，请分类）**：重置令牌并发消费 Python 无 status 守卫（READ COMMITTED
   可双消费）；Java `UPDATE ... WHERE id=? AND status='approved'` 守卫保证严格一次（任务卡
   验收 D 要求），顺序流与 Python 一致。见 endpoints-matrix.md §6。
5. **求值顺序修正**：golden 证明 change-password 401（依赖）先于 422（体校验）先于 404；
   logout 401 先于 404；login/reset 无依赖故 422 先于 404。矩阵 §0 已固化，
   AuthController 按此实现。
6. **近似/未冻结项**：NaN/Infinity JSON 字面量（Python 接受走字段校验、Java json_invalid）；
   json_invalid pos 对复杂嵌套文档未逐形冻结；secure-headers 中间件头属平台层未实现。
   golden-diff.md 已列。
7. platform 零改动；未触碰 admin/**、共享配置、DDL。PG timestamptz 参数用
   OffsetDateTime（JDBC 不隐式转换；Python 驱动行为等价）。
